# Auto wear log and cost per wear

Feature #2 of the portfolio redesign. Branch `feat/wear-log`, cut from `feat/camera-roll-import`
(17861cd). Research: KB `knowledge/outfitted-research-2026-10.md`, item 2: "match outfit selfies
to closet items by embedding; unworn 60+ days → resale nudge". Competitors make you log each
wear by hand; here a photo does it.

## Goal

Drop photos of what you wore and the app logs a wear for every closet item it recognises. A
new `Wear` tab shows cost per wear for each item and nudges you about clothes you haven't worn
in 60 days.

Done when:
- A user can pick up to 30 outfit photos on the Wear tab, watch progress, check the matched
  items per photo (untick a wrong match, add a missed one, fix the date), and log the wears.
- Each photo's date comes from its EXIF `DateTimeOriginal`, else the file's modified date.
- The Wear tab shows: wears in the last 30 days, average cost per wear, items idle 60+ days;
  a `Sell or donate?` list of idle items; every owned item ranked by cost per wear, with an
  inline price field for items that have none; and the last 14 days of logged wears.
- An item can be logged by hand (`Wore today`) from the idle list and the ranking.
- Logging the same item twice on one day counts once.
- Unit tests cover the pure logic; `npm run verify` passes; screens are checked by eye at
  1440 and 390 in the KB shots harness with mocked APIs (the database is not trusted yet).

## Flow

```
pick photos ─► EXIF date ─► downscale ─► POST /api/import/detect (reused), 3 at a time
            ─► embed each crop (FashionSigLIP worker, reused)
            ─► match each crop to the closet ─► review per photo ─► POST /api/wear
closet: GET /api/wear/closet ─► items with no embedding are embedded from their image
        in the same worker and saved with PATCH /api/items/[id] (backfill)
```

1. **Pick.** `<input type="file" accept="image/*" multiple>`, capped at 30 (toast on extras).
2. **Date.** Read EXIF `DateTimeOriginal` from the original JPEG bytes (first 128 KB) before
   downscaling strips it. Pure parser, no dependency. Fallback: `file.lastModified`. Shown as
   a date field in review so the user can fix it.
3. **Detect + embed.** Same calls as the importer.
4. **Closet.** `GET /api/wear/closet` returns owned items `{ id, category, cloudinaryUrl,
   notes, embedding | null }`. Items saved by the importer already have an embedding. Older
   items (upload, camera, product search) do not: the flow embeds their Cloudinary image in the
   same worker and saves it, so the next run skips them.
5. **Match.** Pure. For each crop, the closet item with the highest cosine in the same
   category; a match when cosine ≥ 0.85. One item per photo at most (two crops on one item keep
   the higher score). The threshold is a starting value, not measured: backfilled items embed a
   background-removed cutout, so their scores run lower than crop to crop.
6. **Review.** One row per photo: photo thumbnail, date field, matched items as small tiles
   (tick on, tap to untick), `Add item` opens a closet picker, and a caps note
   `2 not in your closet` for crops with no match. Footer: `Log 9 wears`.
7. **Log.** `POST /api/wear` `{ entries: [{ itemId, wornOn, source }] }`, one call. Server: auth,
   validate (≤ 500 entries, `YYYY-MM-DD`, not in the future, items owned by the user), insert
   with `onConflictDoNothing` on `(clothing_item_id, worn_on)`. Returns `{ added }`.

## Cost per wear

- `price` stays free text (it comes from Google Shopping, e.g. `$1,299.00`, `CA$45`). A pure
  `parsePrice` reads the first number into cents; no number → no price.
- Cost per wear = price / wears. No wears → the full price, shown as `Not worn yet`. No price →
  `Add price` field; saving it calls `PATCH /api/items/[id]` with `price` (now accepted,
  stored normalised as `$12.50`). One currency symbol (`$`); multi-currency is out of scope.
- Idle: owned, and days since the last wear (or since it was added, if never worn) ≥ 60.
- Ranking: worst value first (highest cost per wear), so the list reads as "wear these more".

## Data

New table `wear_logs`:

| column | type | note |
|---|---|---|
| `id` | text pk | uuid |
| `user_id` | text fk users | cascade |
| `clothing_item_id` | text fk clothing_items | cascade |
| `worn_on` | text | `YYYY-MM-DD`, the user's local date |
| `source` | text | `photo` or `manual` |
| `created_at` | text | default now |

Unique index on `(clothing_item_id, worn_on)`. Migration `0002_*` via `drizzle-kit generate`
(offline); applying it waits, like `0001`. `wear_level` on `clothing_items` is left alone.

`GET /api/wear` returns `{ logs: [{ itemId, wornOn }] }` for the user. Stats are computed in
the browser from the logs and the wardrobe store, with a pure `wearStats(items, logs, today)`.

## Options considered

| Option | For | Against |
|---|---|---|
| **Photo → detect → embed → match in the browser (picked)** | Reuses #1 end to end; no new paid call; review fixes mistakes | First run downloads the 94 MB model; untuned threshold |
| Ask Gemini to pick items from the closet list per photo | No model download | Text only; one paid call per photo with the whole closet in the prompt |
| Manual logging only (Whering, Stylebook style) | Simple | It's the pain point the research names |
| Match server side with pgvector | Scales to big closets | Database is unreliable; pgvector unverified on the project |

## Files

- `lib/wear/exif-date.ts`: EXIF `DateTimeOriginal` from JPEG bytes (pure).
- `lib/wear/match.ts`: match crops to closet items (pure, reuses `cosine`).
- `lib/wear/price.ts`: `parsePrice`, `formatCents` (pure).
- `lib/wear/stats.ts`: per-item wears, last worn, cost per wear, idle; summary (pure).
- `lib/wear/log-input.ts`: validate `POST /api/wear` bodies (pure).
- `db/schema.ts` + `db/migrations/0002_*`: `wear_logs`.
- `app/api/wear/route.ts` (GET, POST), `app/api/wear/closet/route.ts` (GET).
- `app/api/items/[id]/route.ts`: accept `price` and `embedding`.
- `components/wear/wear-flow.tsx`: the photo overlay (pick, progress, review, log).
- `app/(app)/wear/page.tsx`: the Wear tab. `components/app-nav.tsx`: `Wear` tab.
- Tests: `lib/wear/*.test.ts`, already run by `npm test`.

## Out of scope

- Marking a whole saved outfit as worn (good next step, small).
- Resale listing itself: the nudge says how long; selling is outside the app.
- Multi-currency prices; undoing a logged wear.
- Tuning the 0.85 / 0.88 thresholds: needs real photos.

## Build order

1. Pure logic test-first: price, stats, match, exif-date, log-input.
2. Schema + migration; `/api/wear`, `/api/wear/closet`; items PATCH gains `price`, `embedding`.
3. Wear flow overlay.
4. Wear page + nav tab.
5. KB harness screens `wear`, `wear-progress`, `wear-review` (mocked APIs); check by eye at
   1440 and 390; `npm run verify`; scan; ask "Push?". Never merge to main.
